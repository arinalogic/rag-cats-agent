# RAG-агент с Pinecone

Учебный проект: ИИ-агент, который перед ответом ищет информацию в векторной базе знаний **Pinecone** (подход RAG — Retrieval-Augmented Generation, «генерация с опорой на найденные данные»).

Что умеет агент:

- **Искать ответ в базе знаний** — находит в Pinecone фрагменты текста, самые близкие по смыслу к вопросу, и отвечает на их основе.
- **Читать страницы по ссылке** — скачивает веб-страницу, вытаскивает из неё основной текст, режет на куски (чанки) и сохраняет в Pinecone.
- **Обращаться к внешнему API** — получает случайный факт о кошках из открытого API [catfact.ninja](https://catfact.ninja/fact) и переводит его на русский.

Агент построен на LangChain (`create_agent`). Модель чата — `gpt-4o-mini`, модель эмбеддингов — `text-embedding-3-small`. Запросы к моделям OpenAI идут через ProxyAPI.

---

## Три части задания и где они в коде

Весь код находится в одном файле — `main.py`.

### 1. Подключение к Pinecone и тестовый запрос

| Что | Где в `main.py` |
|---|---|
| Чтение ключей из `.env`, подключение к Pinecone, проверка, что индекс существует | `RAGAgent.__init__` |
| Тестовый запрос: статистика индекса (сколько в нём векторов) | `RAGAgent.check_connection` |
| Поиск фрагментов по смыслу (k = 3) | `RAGAgent.search` |
| Демонстрация в терминале | `demo_connection` (раздел 1), `demo_search` (раздел 3) |

### 2. Обработка URL: парсинг, чанки, эмбеддинги, сохранение

| Что | Где в `main.py` |
|---|---|
| Проверка ссылки (`http://` или `https://` и домен) | `is_valid_url` |
| Скачивание страницы с таймаутом и обработкой ошибок | `download_page` |
| Очистка HTML и извлечение основного текста | `extract_main_text` (+ `remove_noise_elements`, `find_content_area`, `is_stop_heading`) |
| Нарезка на чанки, отбор коротких, удаление старых чанков, сохранение | `RAGAgent.add_url` |
| Удаление старых чанков той же ссылки | `RAGAgent.delete_old_chunks` |
| Инструмент для агента | `add_url_to_knowledge_base` (внутри `_make_add_url_tool`) |
| Демонстрация в терминале | `demo_add_url` (раздел 2) |

### 3. GET-запрос к открытому API случайного факта о кошках

| Что | Где в `main.py` |
|---|---|
| Адрес API | константа `CAT_FACT_API_URL = "https://catfact.ninja/fact"` |
| GET-запрос, разбор JSON, обработка ошибок | инструмент `call_api` |
| Демонстрация: прямой вызов и вызов через агента | `demo_api` (раздел 4) |

**Запрос:** `GET https://catfact.ninja/fact` с заголовком `User-Agent`, таймаут 15 секунд. Ключ не нужен.

**Ответ:** JSON, из которого берётся поле `fact` (текст факта на английском). Если API не ответило, вернуло ошибку, прислало не JSON или в ответе нет поля `fact`, инструмент возвращает агенту понятное сообщение об ошибке, а не «роняет» программу.

## Как это работает

```
ссылка → текст страницы → чанки → эмбеддинги → Pinecone → поиск → ответ
```

1. **Ссылка.** Проверяется, что это настоящий адрес сайта (`is_valid_url`).
2. **Текст страницы.** Страница скачивается через `requests` (`download_page`). BeautifulSoup удаляет «мусор»: скрипты, стили, меню, подвал, таблицы, номера сносок, а также служебные блоки Википедии (навигация, оглавление, карточки). Текст собирается из заголовков `h2`/`h3`, абзацев `p` и пунктов списков `li`. На разделах «Примечания», «Литература», «Ссылки», «См. также» сбор останавливается.
3. **Чанки.** `RecursiveCharacterTextSplitter` режет текст на куски по 1000 символов с перекрытием 200 символов, чтобы мысль на границе двух чанков не потерялась. Чанки короче 100 символов отбрасываются. В метаданные каждого чанка записывается ссылка-источник (`source`).
4. **Эмбеддинги.** Каждый чанк превращается в вектор из 1536 чисел моделью `text-embedding-3-small`.
5. **Pinecone.** У каждого чанка постоянный id вида `<md5-хеш ссылки>-<номер>`. Перед сохранением старые чанки этой же ссылки удаляются (поиск id по префиксу), поэтому повторная загрузка страницы не создаёт дубликатов.
6. **Поиск.** Вопрос тоже превращается в эмбеддинг, и Pinecone возвращает 3 самых похожих по смыслу фрагмента (`similarity_search`).
7. **Ответ.** Агент получает найденные фрагменты через инструмент `search_knowledge_base` и формулирует ответ. Если в базе ничего не нашлось, он должен честно об этом сказать (так написано в системном промпте).

## Установка (Windows PowerShell)

Нужен Python 3.10 или новее (в коде используется запись типов вида `RAGAgent | None`).

Откройте PowerShell в папке проекта и выполните:

```powershell
# 1. Создать виртуальное окружение в папке venv
python -m venv venv

# 2. Активировать его (в начале строки появится (venv))
.\venv\Scripts\Activate.ps1

# 3. Установить зависимости
pip install -r requirements.txt
```

Если PowerShell не даёт запустить `Activate.ps1` из-за политики выполнения скриптов, разрешите локальные скрипты для текущего пользователя и повторите активацию:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

## Настройка `.env`

Ключи хранятся в файле `.env`, а не в коде. Так они не попадут в Git (`.env` указан в `.gitignore`), и код можно спокойно показывать другим людям.

Скопируйте шаблон и заполните значения:

```powershell
Copy-Item .env.example .env
```

| Переменная | Что это | Где взять |
|---|---|---|
| `PINECONE_API_KEY` | Ключ доступа к Pinecone | Личный кабинет [Pinecone](https://app.pinecone.io) → раздел **API Keys** |
| `PINECONE_INDEX_NAME` | Имя индекса в Pinecone | Имя, которое вы дали индексу при создании (см. ниже) |
| `OPENAI_API_KEY` | Ключ для моделей OpenAI | Личный кабинет [ProxyAPI](https://proxyapi.ru) → раздел с ключами API |
| `OPENAI_BASE_URL` | Адрес, куда отправлять запросы к OpenAI | Адрес OpenAI-совместимого API из документации ProxyAPI |

Если какая-то переменная не задана, программа сразу сообщит об этом: `Переменная ... не задана в файле .env` (функция `get_env`).

### Индекс Pinecone

Индекс нужно создать заранее в личном кабинете Pinecone, программа его не создаёт, а только проверяет, что он существует. Параметры:

- **Dimension (размерность):** `1536` — столько чисел выдаёт модель `text-embedding-3-small`;
- **Metric (метрика):** `cosine`.

Если размерность индекса не совпадёт с размерностью эмбеддингов, Pinecone не даст сохранить векторы.

## Запуск

```powershell
python main.py
```

Программа по очереди выполняет четыре демонстрационных раздела. Каждый раздел сам перехватывает свои ошибки, поэтому даже если один из них упадёт, следующие всё равно выполнятся.

```
🤖 Демонстрация RAG-агента
==================================================

1️⃣ Проверка подключения к Pinecone
✅ Подключение успешно. Векторов в индексе: <число>

--------------------------------------------------

2️⃣ Загрузка страницы в базу знаний
🌐 https://ru.wikipedia.org/wiki/Домашняя_кошка
✅ Сохранено чанков: <число>

--------------------------------------------------

3️⃣ Поиск по базе знаний
❓ Вопрос: Сколько живёт домашняя кошка?

📄 Фрагмент 1
<первые 200 символов фрагмента>
🔗 Источник: https://ru.wikipedia.org/wiki/Домашняя_кошка
... (всего до 3 фрагментов)

--------------------------------------------------

4️⃣ Запрос к внешнему API
🐱 Факт из API: <факт на английском>

❓ Вопрос: Получи из API интересный факт про кошку
🔧 Агент вызвал инструмент: call_api
💬 Ответ агента: <факт, переведённый на русский>

==================================================
✅ Демонстрация завершена
```

Что происходит в разделах:

1. **Подключение к Pinecone** — создаётся агент и запрашивается число векторов в индексе.
2. **Загрузка страницы** — статья Википедии «Домашняя кошка» обрабатывается и сохраняется в Pinecone.
3. **Поиск** — по вопросу «Сколько живёт домашняя кошка?» выводятся найденные фрагменты и их источник.
4. **Внешнее API** — сначала `call_api` вызывается напрямую, затем тот же запрос задаётся агенту, и он сам решает вызвать инструмент `call_api`.

Ошибки печатаются в терминал со значком ❌. Подробные логи (этапы обработки страницы, число чанков, ошибки с трассировкой) пишутся в файл `rag_agent.log`, чтобы не засорять консоль.

## Ограничения и что можно улучшить

**Ограничения:**

- Тестовая ссылка и вопросы зашиты в коде (`if __name__ == "__main__"`), интерактивного диалога с агентом нет.
- Парсер страниц настроен в первую очередь на Википедию. На других сайтах текст может извлекаться хуже, а страницы, которые рисуются через JavaScript, не прочитаются совсем: `requests` получает только исходный HTML.
- Таблицы удаляются целиком, поэтому данные из таблиц в базу знаний не попадают.
- Агент не помнит предыдущие сообщения: каждый вызов `ask` — новый разговор.
- В ответе агента не указываются источники, хотя они хранятся в метаданных чанков.
- Факт о кошках приходит на английском, перевод делает модель.
- Индекс Pinecone нужно создать вручную заранее.

**Что можно улучшить:**

- Добавить интерактивный режим: ввод вопросов и ссылок с клавиатуры в цикле.
- Добавить память диалога, чтобы агент учитывал предыдущие сообщения.
- Выводить в ответе ссылки на источники найденных фрагментов.
- Показывать оценку похожести (score) найденных фрагментов и отсекать слабо подходящие.
- Сохранять в метаданные заголовок раздела, к которому относится чанк.
- Вынести настройки (размер чанков, число фрагментов `k`, модели) в `.env` или отдельный файл конфигурации.
- Разделить `main.py` на модули: загрузка страниц, работа с Pinecone, агент, демонстрация.
- Написать тесты, например для `is_valid_url` и `extract_main_text`.
